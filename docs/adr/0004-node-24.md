# ADR 0004: Node 24 LTS

## Status

Accepted (2026-11-26).

## Context

`docs/specs/README.md` and `docs/specs/00-architecture.md` name Node 22. They do not mention Node 24. ADR 0001 left the choice open and rejected pinning Node 24 during Ticket 0. `docs/specs/OPEN-QUESTIONS.md` said Ticket 1 had to choose before it pinned a runtime.

The nodejs.org dist index, read on 2026-11-26, lists v24.22.3 (2026-11-10) with `lts` set to `Krypton`. The same index lists v26.13.1 (2026-11-10) with `lts` set to `Lithium`. Node 24 is an LTS line. It is not the only one.

Andy decided this ticket uses Node 24 LTS so the runtime matches his other repositories. Those pin the line, not a patch: `.nvmrc` contains `24`, and `engines.node` is `>=24 <25`.

## Decision

- The runtime is the Node 24 LTS line (Krypton).
- `.nvmrc` contains `24`. `actions/setup-node` reads that file, so CI follows the 24 line rather than a frozen patch.
- `engines.node` is `>=24 <25`. `.npmrc` sets `engine-strict=true`, so a different major fails install.
- `packageManager` is `pnpm@10.34.9`. That was `latest-10` on the npm registry on 2026-11-26. `engines.pnpm` is `>=10.34.9 <11`.

## Alternatives

- Node 22, as the specs write it. Rejected. Andy chose Node 24 for this ticket. The spec files stay as written. This ADR is the record.
- Node 26 (Lithium), which the same dist index already marks LTS. Rejected. The decision is the Node 24 line his other repositories already pin. Moving to 26 needs its own ADR.
- Pinning the patch `24.22.3` in `.nvmrc`. Rejected. The other repositories pin the line so a 24 security release is picked up by `setup-node`. The newest 24 on the index at decision time was 24.22.3. That fact is not a pin.
- pnpm 12.23.0, the `latest` dist-tag on the npm registry on 2026-11-26. Not chosen. pnpm 10.34.9 is the newest 10.x that day, the same major already in use on the Node 24 repositories. A new pnpm major is a separate decision.

## Consequences

- Ticket 1 and later TypeScript code run on Node 24. Local and CI both do. Node 22 in the specs is not the runtime.
- `setup-node` may move within 24 as Node publishes patches. It will not move to 25 or 26 without an engines change.
- pnpm 10 blocks dependency build scripts unless they are approved. This repo approves a script only when install says it needs one.
- Python services stay on the versions spec 00 names when those services are built. This ADR does not choose a Python version.
